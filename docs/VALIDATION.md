环境：独立 Debian 12 x86_64 服务器检出，单核、约 1 GiB 内存，Node.js 24.20.0。全部项目测试串行运行，使用合成账号和加密资料库。测试期间预加载网络保护，仅允许回环请求；Telegram 单元/API 测试使用模拟传输。

## 修复与证据

- `Vault.save` 原来固定同步当前目录下的 `runtime/`，即使资料库实际位于其它目录；在无 `runtime/` 的独立工作目录保存自定义资料库会抛出 ENOENT，且同步的目录不对应本次原子重命名。现在同步资料库实际父目录，并保证关闭目录描述符。
- 新增绝对路径和相对路径两项回归：原代码均失败，修复后均通过。测试确认不会创建无关 runtime 目录、重新读取内容一致、资料库权限600。
- 监督器挂起测试曾用历史任意进程的 start 事件判断替换进程已经就绪；单核环境中，新进程在完成初始化前就被模拟检查连续失败重启。测试改为匹配当前 childPID，保留5秒等待上限和严格一次重启断言；生产监督器逻辑未改动。
- README 的 HTTPS 健康检查证书身份说明更正为 `IP:127.0.0.1`；同时说明反向代理可按需使用 `DNS:vps-internal`，并补充降权测试所需的目录权限。
